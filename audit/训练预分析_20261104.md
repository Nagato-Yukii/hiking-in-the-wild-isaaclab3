# HikingLab3 训练预分析（2026-11-04）

后续已完成双方2048环境×100更新的[实际速度对照](速度对比_2048环境_100更新.md)：Newton稳态吞吐为原Instinct/PhysX的1.423倍。下文“没有PhysX对照”描述的是本预分析形成时的状态，现以新实测报告为准。

本次核对原始代码、当前实现与 `logs/learning-space-final` 的实际配置，并运行独立的短容量测试。未改动任务奖励、随机化、地形、观测或 PPO/AMP 超参数。本报告区分代码事实、实测和待验证推断；不能视为原论文效果复现。

## 训练效果与 Newton / MJWarp

Newton 是物理后端，MJWarp 是当前使用的 GPU 求解器；两者在此处是一套配置。当前为无 Kit 的 Newton/MJWarp，原 Hiking 为 Isaac Sim/PhysX。原版深度传感器本来也是 ray casting，不能把收益归因于“把原 RTX 相机换成射线”。当前还更换了相机封装、AMP 参考机器人管理方式，端到端比较会包含这些实现差异。

已完成的 256 环境、1000 更新：6,144,000 transitions / 918.23 秒 = 6,691 transitions/s（训练循环均值，含首次边缘检测等开销，不含环境初始化）。末 100 更新平均日志吞吐 7,388 transitions/s，collection 0.6455 秒，learning 0.1864 秒；collection 占 77.6%，但包含物理、感知、推理、奖励、reset 和参考运动处理，不能称为物理引擎耗时。没有相同配置的 PhysX 对照，尚不能断言 Newton 更快。

当前物理步长 0.005 秒、decimation=4、每物理步 2 个子步，因此内部积分步长 0.0025 秒、策略 50Hz。启用 CUDA graphs、implicitfast、Newton 接触检测，nconmax=300、njmax=1000。不能只比较名义 dt；减少子步或接触容量会改变接触质量或丢失接触，必须同时核验台阶穿透、滑移、冲击和约束溢出。[官方 MJWarp 调优说明](https://isaac-sim.github.io/IsaacLab/develop/source/how-to/solver_tuning_mjwarp.html)。

从训练效果推断：接触材料与积分器差异会改变脚底滑移和 AMP 看到的动作分布；未必更好或更差。增加环境数提高批次多样性，也改变每次更新样本量。应比较相同总 transitions 下的成功率，同时报告达到同一成功率的墙钟时间，而非只比较更新次数或视频。

原配置每次更新 4096×24=98,304 transitions；256 环境只有 6,144，是其 1/16。现有 256×1000 的总采样量相当于原配置 62.5 次更新的数量，**不代表学习过程等价**。1024 或 2048 环境的 30000 更新，也分别只有原配置 1/4 或 1/2 的采样量。增加 rollout 长度、minibatch 数或梯度累积都可能改变 GAE、优化和 adaptive KL 调度，不能无说明地当作严格同实验。

原论文使用 4096 agents / RTX4090，且通用 walking 后另有 stair、platform、running 三类专用策略各额外 40000 次更新；本地目前只验证通用 walking 管线。[论文 Appendix A.8/B/C](https://arxiv.org/html/2601.07718v2)。

## 当前真正启用的随机化

| 项目 | 原始鞋版与本地配置 | 需要区分的实现语义 |
|---|---|---|
| 接触材料 | startup：摩擦范围 0.3–1.6，恢复系数 0.05–0.5 | 原 PhysX 分静/动摩擦、64 buckets；Newton 只有单一 μ，逐 shape 连续采样，忽略 dynamic_friction_range、num_buckets、make_consistent |
| base reset | x/y ±0.1m，yaw ±0.1rad，线/角速度六维各 ±0.2 | 初始状态分布，不是行走中外力推搡 |
| joint reset | 相对默认关节位置 ±0.15rad，速度偏移 0 | 训练启用；官方 PLAY 设置会改为无偏移 |
| actor 本体噪声 | 角速度 ±0.2，重力投影 ±0.05，关节位置 ±0.01，关节速度 ±0.5 | 均匀噪声，随后角速度×0.25、关节速度×0.05；critic 与 AMP 不加这类噪声 |
| 深度 | crop、Gaussian blur 3×3/σ=1、归一化；37 帧缓存取 8 帧、stride5 | blur 是确定性预处理；导入的随机深度噪声/artifact 并未加入原 pipeline |
| 任务与数据 | 随机地形、目标/速度、standing、AMP 起点和 50% 镜像 | 属于任务分布/数据增强，不全部属于动力学域随机化 |

原版最终鞋版及当前均没有 mass、COM、惯量、PD gain、motor strength、外力推搡、本体观测延迟随机化。原 rough 分支有 delayed PD，但后续鞋版整体替换 robot 恢复 implicit actuator，不能只读前半段配置就认定动作延迟漏移植。

深度延迟两边均采 U(0,1) 后使用 `(整数-delay).long()`，实际几乎总是一帧（20ms），不是均匀离散 0/1 帧抖动。当前深度先裁到 2.5m 再模糊，原 pipeline 先模糊后归一化/截断，远近交界输入不完全相同。

地形为 10×20 tiles，每 tile 8×8m；初始等级0–5、按表现升级/降级。普通台阶高0.05–0.23m，高台0.05–0.45m，gap宽0.1–0.7m/深0.4–0.6m，坡度参数0–0.7，Perlin幅度0–0.1m；边墙概率0.3。坡度参数在原/当前代码中直接按高宽比使用（最大约35°），虽然配置注释标为radians，不能直接解读成0.7rad。目标从50个平坦候选点选择，命令8–12秒重采样，standing概率5%。地形每次运行按固定 seed 生成，reset 并非重新生成整张地图。

AMP 仍使用官方 walking 数据和 50% 镜像，但公开 NPZ 无 clip IDs。本地从拼接序列全局前90%的有效起点采样并过滤跨缝窗口；原实现按 clip 权重，再在各 clip 前90%取起点。相位/动作权重可能变化，不能称采样分布严格一致。

后续旧版实际启动补充：同一公开NPZ被原加载器识别为**1条轨迹**（18981个有效帧）。因此上述多clip权重差异是一般机制差异，不能据此断言本数据集实际发生了多clip重加权；本地额外的跨缝过滤等仍需单独比较。

证据：[`task_terms_cfg.py`](../hikinglab3/task_terms_cfg.py)、[`observations.py`](../hikinglab3/observations.py)、[`motions.py`](../hikinglab3/motions.py)、[官方配置快照](upstream/parkour_env_cfg.py)、[原鞋版覆盖](upstream/g1_parkour_target_amp_cfg.py)、[Newton 材料实现](../../IsaacLab-3.0.0/source/isaaclab_newton/isaaclab_newton/envs/mdp/events.py)。

## 台阶边界如何处理

1. 在地形三角网格上检测相邻面法向夹角 >70° 的锐边（凹凸均可能入选），按方向转角 <30° 贪心拼接；拟合线偏差硬编码 <0.05m，最少2点。不是相机图像边缘检测。
2. 每条边附半径5cm的**虚拟圆柱惩罚区**。不是实体碰撞圆柱、圆角台阶，也不直接限制脚的位置。有限线段之外不算圆柱内；重叠区取最大穿透深度。
3. 每只鞋底用10×5×2=100个体积点，两脚共200点；区域x=[−0.025,0.12]m、y=[−0.03,0.03]m、z=[−0.063,−0.023]m。
4. 每个策略步贡献为 `−4 × 0.02 × Σ penetration_i × (speed_i + 1e−6)`，对全部点求和。移动穿越边界惩罚较大，不需要实际接触标志；静止踩在区域里几乎没有该项惩罚，所以它不是硬安全保证。

现有完整地图训练检测到44,347条边，日志边缘惩罚有非零值，机制确实参与训练。物理地形 `slope_threshold=1.0` 在水平0.05m网格上把超过0.05m的相邻高度跳变做成竖直侧壁；它与70°检测阈值是两回事。当前完整地图仍为 mesh collider，并未整体切为 heightfield collider。

发现尚未对齐的一处：原 importer 在检测前合并重合顶点、清理重复面/悬空点；本地 importer 只保存原始拼接 mesh。tile 接缝拓扑和边缘集合可能不同，影响大小尚未量化。应在正式长训练前补齐并对固定地图比较 edge 集合。当前另增加了圆柱中心线除零保护；这有利于数值稳定，但也是实现差异。

体积点速度使用线速度加 ω×偏移；本地线速度字段为 COM 速度而偏移相对 link 原点，原实现也有相似混用，宜加刚体解析运动检查，不能未经验证归因为本次移植的新回归。

证据：[`edges.py`](../hikinglab3/edges.py)、[`safety.py`](../hikinglab3/mdp/safety.py)、[`terrain_importer.py`](../hikinglab3/terrain_importer.py)、[原 importer](../vendor/InstinctLab/source/instinctlab/instinctlab/terrains/terrain_importer.py)。

## 环境容量测试

当前可用机器为 RTX5070Ti 16GB、32GB主存，开始时约15GB显存与24GB主存可用。容量测试使用原10×20地形、真实深度历史、MoE、AMP、24步rollout、5 epochs/4 minibatches，随机初始化独立训练；每档12次完整更新，跳过前3次统计吞吐。没有以纯场景加载代替训练容量。

| 并行环境 | 完整更新 | 预热后 transitions/s | 采样设备显存峰值 | 全程主存最低可用 |
|---|---:|---:|---:|---:|
| 1024 | 12/12 | 13,547 | 7.35GiB | 14.92GiB |
| 2048 | 12/12 | 16,017 | 10.72GiB | 14.61GiB |
| 4096 | 0，显存余量保护停止 | — | 15.11GiB | 14.16GiB |

1024 的稳态 collection/learning 为1.285/0.529秒，2048为2.080/0.988秒。从1024增至2048，初期训练吞吐仅提高约18.2%，并不翻倍。两档均完成判别器更新、参数有限值检查。历史256训练后期7,388 transitions/s使用的是不同学习阶段策略，不能把它与这两档随机初始策略当作严格同状态加速对照。

4096能完成场景与训练器初始化，但进入训练后、首个完整更新结束之前，设备已用15477MiB、仅剩364MiB，触发768MiB余量保护并结束本次前台子进程。**这是保护停止，不是已观察到CUDA OOM；也没有证明4096完整训练通过。** 当时主存仍有约14.16GiB可用，限制主要来自显存。原样4096不适合作为本机的已验证长期配置；当前2048有约4.75GiB最小空闲显存，作为后续完整验证起点更合理，1024更保守。

工具为 [`benchmark_capacity.py`](../scripts/benchmark_capacity.py)：前台子进程、0.5秒间隔采样设备总显存与系统可用内存，显存余量低于768MiB或主存低于4096MiB时停止本次子进程。采样峰值为真实峰值的下界，包含桌面等其他 GPU 使用；短测试成功不保证长期及最坏接触场景成功。原始记录：[1024](../logs/capacity-20261104-1024/capacity.json)、[2048](../logs/capacity-20261104-2048/capacity.json)、[4096](../logs/capacity-20261104-4096/capacity.json)。

仅 PPO/AMP 持久 rollout 张量（float32 actor/critic obs、AMP两组、action/mean/std、标量和done）约为：1024环境1.118GiB、2048环境2.235GiB、4096环境4.471GiB，尚未计入物理求解器、射线、相机历史、mini-batch拷贝、前后向激活、CUDA workspace和地形。不能用剩余显存除以机器人USD大小估算容量。

若按2048短测吞吐外推，30000更新约25.6小时；采够原4096×24×30000的29.49亿 transitions 约51.1小时。这只是初始策略吞吐预算，不是收敛时间承诺，也未覆盖高难度接触、运行抖动及正式评估。

若需要严格保留原4096×24的优化批次，优先考虑共享 actor/critic 的同一深度数据（现有重复存储约1.6875GiB），以及每个原minibatch内部微批次梯度累积。后者须统一损失归一化、累积后梯度范数裁剪、每个原minibatch一次Adam和KL调度，并对AMP梯度惩罚同步处理；仅增加minibatch数量并不等价。网络参数本身只有约480万，权重/梯度/Adam状态约73MiB，缩小网络不是主要显存优化点。以上优化本次未实施。

正式比较应固定地图/重置/命令/观测/AMP/优化配置，记录启动与稳态时间、峰值显存/内存、接触溢出、穿透和滑移。学习质量用固定难度、每类地形1000次、15秒内距离目标≤0.25m且不触发失败的成功率，以及多seed均值/离散度；增加深度置零或打乱消融，才能证明策略确实利用了视觉。当前短测试没有回答最终收敛和sim-to-real效果。
