# IsaacLab 3.0 移植版、官方公开代码与论文：设计差异核查

核查日期：2026-11-05。只审计，未改训练配置、权重或重启训练。

结论：本地是第三方 G1 Hiking 移植，不是官方发布的 Hiking-for-IsaacLab-3.0；保留了主要任务配置，但尚不具备“与论文实验完全等价”的证据。官方当前公开配置本身也有与论文描述不一致之处。

## 版本与证据范围

- IsaacLab：v3.0.0，`e3f7d9ff1f5d7f8280de3ece9000b7117f66bcf4`。
- 本地 vendored 环境：X2 fork `411779fe810f0cb021e177b63ad48d9e15258f05`，使用其保留的 G1 路径。算法来源记录为 instinct_rl `ba45ed231ebbf0a4099cd31d607e2886814fd165`（复制目录，无本地 git 元数据）。
- 本次通过 git ls-remote 固定官方 InstinctLab main 为 `de6b92f01eb155d51f30e8ed1ea7aecd2eb1f057`；下载了核心配置、命令生成、importer、RL 基类配置。三个核心配置与上次审计快照 SHA-256 完全一致。不是对整个官方仓库所有功能做完整审计。
- 论文：[v2，2026-10-13](https://arxiv.org/html/2601.07718v2)。
- 当前本地训练源码与 15000 checkpoint 所在 run 的已记录源码哈希比较：已记录且仍存在的文件无变化。新评估脚本另行添加。
- `scripts/audit_design.py` 的 10 组 AST 定义比较全部通过。这证明选定配置定义一致，不证明底层执行语义、数据分布或数值结果一致。

官方来源：[固定提交](https://github.com/project-instinct/InstinctLab/tree/de6b92f01eb155d51f30e8ed1ea7aecd2eb1f057)。下载文件与哈希见 [provenance.json](upstream_20261105/provenance.json)。

## 一、移植版与官方公开 G1 代码

| 项目 | 官方公开配置/实现 | 本地实际实现 | 判断 |
|---|---|---|---|
| 物理后端 | Isaac Sim / PhysX | Newton / MJWarp，implicitfast，2 内部子步 | 接触、积分和约束不等价；影响未做学习质量因果验证 |
| 控制时序 | dt=0.005，decimation=4，策略 50 Hz | 相同外层时序，内部积分步为 0.0025 | 名义时序一致，不等于物理一致 |
| G1 机器人 | torso-base、29DoF、鞋版；最终覆盖为 implicit PD | 同源模型、动作尺度与 PD 配置 | 没有遗漏最终鞋版应有的 delayed PD：该分支最终本来就是 implicit |
| 地形与课程 | 10×20、8×8m、10 类、初始 0–5；按跟踪表现升降 | 配置 AST 一致 | 课程看速度跟踪，不直接按通关；平均等级不能证明上楼能力 |
| 命令 | Flat Patch 目标，8–12s 重采样、5% standing、到目标 0.4m 停止 | 相同；命令代码差异主要为 Tensor API 与 slice 适配 | 不是遗漏了目标引导，也不是纯随机速度指令 |
| 核心任务奖励 | 26 项及其权重 | AST 一致，修正了 Lab3 单位/API 差异 | 不支持“本地新增存活奖励导致问题”的说法 |
| 外部感知 | 自视角 ray-cast 深度，包含自身链接 | 同类输入；8×18×32 深度历史、stride=5 | 不是盲走；是否实际利用视觉仍需遮蔽/打乱消融 |
| 深度处理顺序 | crop → blur → 归一化截断 | raw 先截到 2.5m，再 crop → blur → 归一化 | 已确认差异；远近交界像素不等价 |
| 台阶边缘 | 全图 mesh 合并顶点、去重复面、清理无引用点后检测 | `HikingTerrainImporter` 直接保存原始拼接 mesh | 已确认遗漏预处理；检测边集合影响尚未量化 |
| 边缘惩罚机制 | 70° 锐边、30° 拼接、5cm 虚拟圆柱、每脚100体积点，穿透×速度 | 主要机制保留，新增除零保护 | 没有把惩罚区变成实体障碍；静止时该罚分天然很小 |
| 材料随机化 | 静/动摩擦、64 buckets | 单一摩擦系数、连续采样；部分参数被后端忽略 | 同配置数值不等于同随机化分布 |
| AMP 参考 | 原 MotionReferenceManager 与参考状态流程 | NPZ 直接构造状态、连续游标、10 帧历史与50%镜像 | 已重写关键数据通路，未完成逐帧等价测试 |
| AMP 拼接处 | 原加载器对发布 NPZ 识别为1条轨迹 | 额外过滤线速度>10m/s 或关节速度>100rad/s附近窗口 | 本次算得49个异常帧，排除490/18972窗口，约2.58%；不能称分布严格相同 |
| PPO 与网络配置 | 24 步、5 epochs、4 minibatches、4 专家 | 这些显式配置一致 | 有效 batch 受实际 num_envs 影响 |
| 训练规模 | 默认4096环境、30000更新 | 用户本轮2048环境、计划20000；评估保存点为15000 | 15000×2048×24≈7.37亿 transitions，为默认完整训练约25%的样本数；不是收敛等价换算 |

定位：`hikinglab3/{config.py,observations.py,motions.py,terrain_importer.py,task_terms_cfg.py,agent_cfg.py}`；官方快照 `upstream_20261105/`。材料语义见 `IsaacLab-3.0.0/source/isaaclab_newton/isaaclab_newton/envs/mdp/events.py`。

## 二、论文描述与公开代码本身的差异

以下以论文附录 A 的表格/流程对照实际公开 G1 配置，不能全部归为本次移植遗漏。

1. **MoE gate：论文表6写隐藏层 [256]；官方 `rl_cfg.py` 默认 []，parkour agent 未覆盖。本地已保存的 agent.json 也是 []。** 实际实现为输入直接线性映射到4个 gate logits，再 softmax；保留4专家，但并非论文所列门控结构。不能直接给现有 checkpoint 改成 [256] 并期待兼容。
2. **深度随机噪声：论文 A.4 描述高斯噪声、视差失效和 OOD 替换；官方当前 G1 noise_pipeline 仅挂接 crop、blur、normalization，本地同样没有启用这些额外随机项。** Gaussian blur 不等于随机 Gaussian noise。
3. **鞋底高度补偿：论文奖励表写0.035m；公开鞋版 mixin 最终覆盖为0.058m，本地跟随后者。** 不能只看父类或论文表格而误判本地参数。
4. **坡度单位：论文表7标 rad；公开地形函数按 rise/run 使用该参数，本地继承。** 0.7 对应 arctan(0.7)≈35°，不是0.7rad≈40°。
5. **奖励表并非代码逐字语义：** 论文速度越界公式未写逐关节最大1裁剪，而代码有；论文 undesired contact 写任意违规指示量，本地实际使用超阈值 body 数求和（源自框架实现）。这些差异不能通过只比较 weight 排除。

上述论文对照来源：[附录 A](https://arxiv.org/html/2601.07718v2#A1)。公开配置定位见 `upstream_20261105/parkour_env_cfg.py`、`g1_parkour_target_amp_cfg.py`、`rl_cfg.py`；本地 gate 构建见 `vendor/instinct_rl/instinct_rl/modules/moe.py`。

## 三、官方 checkpoint 不等于论文通用策略

当前用于对比的发布包是 `parkour_onboard_preview_stair`，是楼梯专项；本地15000是从零混合地形训练。发布 ONNX actor 是普通 MLP 图，本地是 MoE。现有证据不足以从 ONNX 名称推断完整训练历程或断言它就是论文表格所评估的权重。

论文说明通用 walking 后另有专项后训练，每类额外40000次更新；本地尚未执行这套阶段设计。因此视频比较只能说明“当前两份权重在同一环境的行为差异”，不能隔离出物理后端或移植代码的因果作用。[论文 A.8](https://arxiv.org/html/2601.07718v2#A1.S8)

## 四、上一轮停滞诊断的必要补充

训练里的奖励流是：

`r_train = 0.02 × sum(weighted_task_terms) + 0.25 × r_AMP`

超时样本另有 value bootstrap。PPO 在接收环境奖励后直接添加 AMP；AMP 并没有再乘0.02。此为当前沿用的算法实现，不是本次移植新增的改动。

停滞时任务项 +4.695/秒相当于每步约+0.0939；AMP quad 在0–1范围，对应每步最多+0.25。其实际得分未知，所以仅凭存活奖励明细不能确定完整训练回报偏好，更不能认定某一个奖励项是唯一原因。下一步需要实际读取该 checkpoint 的判别器，比较停滞与运动时的 AMP 分数及参考特征一致性。

本次仍未测量这一判别器分数。490个过滤窗口的分布差异、gate结构差异和物理差异也都没有通过重训练消融验证因果。

## 五、评估与训练应分开解释

现有配对评估统一在 Newton 中、固定挑战几何、关闭观测/材料随机化、移除 root-height 终止，并用0.25m成功阈值。为避免命令先于成功判据停住，命令停止阈值改为0.2m；最大命令设置为[0.55,0.3,1]，允许横向速度，而原训练配置横向上限为0。目标取候选点中远端 +X 目标，而非原训练随机抽样。

双方共享这些设置，所以可以比较两份权重在这套协议下的表现；不能称为原生 PhysX 正式复现或直接对齐论文绝对成功率。详细协议与结果见 [Checkpoint对比报告](Checkpoint对比_15000_vs_官方楼梯.md)。

## 六、优先级建议

1. 先建立公开代码等价基线：AMP逐帧特征/历史/重置/奖励尺度对照，深度处理顺序对照，相同 mesh 清理前后边集合对照。
2. 用相同初始化、AMP数据、batch与样本预算比较 PhysX/Newton 的学习质量；不要把已有吞吐优势当成学习优势。
3. 单独建立论文配置实验：显式 gate=[256]、完整深度扰动，以及专项后训练；与公开代码配置分开命名和记录。
4. 在这些检查之前，不建议通过增大“不前进”惩罚来掩盖实现差异；修改奖励应另设消融组。

过去修复的全零速度限值和重力向量单位错误发生在旧测试阶段，15000 run 已包含修复；本次未发现它们重新出现。当前仍应称为“可运行的移植基线”，不能称为论文效果已复现。
